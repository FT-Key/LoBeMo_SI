## Problema
Solo `console.error`. Sin trace IDs, sin estructura (RNF-12).

## Solución implementada
1. Instalado `pino` (dependencia nueva en package.json).
2. Creado `src/lib/logger.ts`:
   - Logger base pino con `service: lobemo-si`, `env`, timestamp ISO.
   - Nivel vía `LOG_LEVEL` (default `debug` en dev, `info` en prod).
   - Helpers: `REQUEST_ID_HEADER`, `getRequestId(request)`, `childLogger(ctx)`,
     `getRequestLogger(request, extra)`, `logApiError(route, error, ctx)`.
   - Contexto estándar: requestId, userId, entidad, acción.
3. `src/middleware.ts`: genera/propaga `x-request-id` (crypto.randomUUID),
   lo inyecta en los request headers y lo devuelve en la respuesta.
4. Reemplazados todos los `console.*` en código de servidor:
   - 56 API routes + `src/auth.ts` + `src/app/(auth)/login/actions.ts`
   - `console.error("msg:", err)` → `logger.error({ err }, "msg")`
   - Login: `console.log` con datos sensibles → `logger.debug/warn` sin secretos
     (se eliminó el log de longitud del token).
   - `prisma/seed.ts` se deja con `console.*` (script CLI, no es producción).
5. Test nuevo `src/lib/logger.test.ts` (5 tests: niveles, requestId, child, logApiError).
