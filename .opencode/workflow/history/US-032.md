# US-032: Upload de Documentos PDF con Cloudflare R2

## Estado
🔄 **En Progreso** — PR #71 abierto hacia dev

## Descripción
Implementar sistema de upload de documentos PDF (y otros tipos permitidos) utilizing Cloudflare R2 como almacenamiento en la nube, reemplazando el mecanismo actual de guardado como data URLs base64 en PostgreSQL.

## Problema Actual
El modelo `Documento` guarda archivos completos como `data:` URLs (base64) en el campo `url` de PostgreSQL. Esto es ineficiente y no escala. El GET de listados devolvía payloads completos de base64.

## Solución
Cloudflare R2 como almacenamiento en la nube con API compatible S3.

## Archivos Creados
- `src/lib/r2.ts` — Cliente R2 con upload, delete, presigned URLs
- `src/app/api/upload/route.ts` — Endpoint upload multipart/form-data
- `src/app/api/upload/[key]/route.ts` — Endpoint delete desde R2
- `src/components/ui/file-upload.tsx` — Componente UI drag & drop
- `prisma/migrations/20260906000000_add_documento_r2_fields/migration.sql`

## Archivos Modificados
- `prisma/schema.prisma` — Campos: `mimeType`, `tamanio`, `storageKey` (unique) en Documento; `url` ahora opcional
- `src/app/api/documentos/route.ts` — POST acepta `storageKey` (R2) OR `url` (legacy base64); GET excluye base64 de responses
- `src/app/api/documentos/[id]/route.ts` — DELETE limpia R2 si `storageKey` existe
- `src/shared/validation/documentos.ts` — Nuevo schema `createDocumentoSchema` con `storageKey`; schema legacy `createDocumentoBase64Schema`
- `src/app/proyectos/[id]/proyecto-detalle.tsx` — Usa componente `FileUpload` en vez de base64 inline; preview maneja R2 y legacy
- `src/app/api/portal/documento/[id]/route.ts` — Soporte para presigned URLs desde R2
- `.env.example` — Variables R2 agregadas
- `package.json` — @aws-sdk/client-s3 + @aws-sdk/s3-request-presigner
