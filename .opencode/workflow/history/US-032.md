# US-032: Upload de Documentos PDF con Cloudflare R2

## Estado
📋 **Backlog** - Pendiente de implementar

## Descripción
Implementar sistema de upload de documentos PDF (y otros tipos permitidos) utilizando Cloudflare R2 como almacenamiento en la nube, reemplazando el mecanismo actual de guardado como data URLs base64 en PostgreSQL.

## Problema Actual
El modelo `Documento` guarda archivos completos como `data:` URLs (base64) en el campo `url` de PostgreSQL. Esto es ineficiente y no escala.

## Solución
Cloudflare R2 como almacenamiento en la nube con API compatible S3.

## Stack Requerido
- Cloudflare R2 (almacenamiento)
- @aws-sdk/client-s3 + @aws-sdk/s3-request-presigner
- Prisma (migración de modelo)
- Next.js API Routes (multipart/form-data)

## Archivos a Crear
- `src/lib/r2.ts` - Cliente R2
- `src/app/api/upload/route.ts` - Endpoint upload
- `src/app/api/upload/[key]/route.ts` - Endpoint delete
- `src/components/ui/file-upload.tsx` - Componente UI

## Archivos a Modificar
- `prisma/schema.prisma` - Campos: mimeType, tamaño, storageKey, subidoPor
- `src/app/api/documentos/route.ts` - Adaptar para R2
- `src/shared/validation/documentos.ts` - Actualizar validación
- `.env.local` - Variables R2

## Migración
- Nueva migración Prisma con campos adicionales
- Script de migración de documentos existentes (data URLs → R2)

## Acceptance Criteria
- [ ] Cuenta Cloudflare R2 configurada
- [ ] API upload funcionando con multipart/form-data
- [ ] Validación MIME types y tamaño
- [ ] Frontend: Componente FileUpload con drag & drop
- [ ] Migración de documentos existentes
- [ ] Audit log para uploads

## Notas
- Bucket: `lobemo-docs`
- Keys: `proyectos/{proyectoId}/{uuid}-{filename}`
- Límite: 25MB por archivo
- MIME types: PDF, imágenes, Office, texto
